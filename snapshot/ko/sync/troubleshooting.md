# simplix-sync 문제 해결

인스턴스 사이에서 메시지를 주고받을 때 발생하는 증상과 원인, 조치를 정리합니다.

| 증상 | 원인 | 조치 |
|---|---|---|
| 메시지를 보낸 인스턴스에 자신의 변경이 반영되지 않음 | 발신 인스턴스는 자신이 보낸 메시지를 받지 않습니다 | 메시지를 보내는 메서드에서 로컬 상태를 직접 변경하세요 |
| 어느 인스턴스에도 메시지가 도착하지 않고 로그에 `SimpliX Sync: local mode (NoOp broadcaster)`가 기록됨 | 모드가 `LOCAL`이거나 브로커의 라이브러리 또는 연결이 없습니다 | `mode: DISTRIBUTED`를 지정하고 브로커의 의존성과 연결을 추가하세요 |
| 재시작한 인스턴스의 상태가 오래된 값임 | 인스턴스가 꺼져 있는 동안 전송된 메시지는 저장되지 않습니다 | 시작할 때 상태를 불러오고 `ReconciliationScheduler`를 실행하세요 |
| 핸들러가 메시지를 디코딩하지 못함 | 인스턴스마다 메시지 클래스의 버전이 다르거나, 채널 이름 하나에 여러 메시지 타입을 사용했습니다 | 이전 버전이 읽을 수 있는 방식으로 필드를 추가하고, 타입마다 채널을 따로 사용하세요 |
| NATS에서 채널의 메시지가 전달되지 않음 | 채널 이름이 유효한 서브젝트가 아닙니다 | 공백이 없고 `.`이나 `-`를 구분자로 사용하는 이름을 지정하세요 |
| 인스턴스마다 카운터 값이 달라짐 | 「1 증가」 같은 지시를 메시지로 보냈고, 메시지가 유실되었거나 중복 적용되었습니다 | 새 값이나 버전을 보내세요. 메시지를 다시 적용하거나 건너뛸 수 있습니다 |
| `simplix.sync.distributed.redis-enabled: false`를 지정해도 Redis가 비활성화되지 않음 | 이 속성을 읽는 코드가 없습니다 | `broker: NATS` 또는 `mode: LOCAL`을 지정하세요 |
