# simplix-license 문제 해결

배포본의 라이선스와 관련해 발생하는 증상과 원인, 조치를 정리합니다.

## 시작과 활성화

| 증상 | 원인 | 조치 |
|---|---|---|
| 애플리케이션이 시작되지 않음 | `ProductIdentity` 빈이 없거나, 검증 키 파일이 없거나 비어 있거나 잘못된 항목이 있거나, 저장소가 저장소 인터페이스 중 하나만 구현했습니다 | 빈을 선언하거나, 파일을 바로잡거나, `LicenseStore`와 `CompromiseCeilingStore`를 함께 구현하세요 |
| 모든 활성화를 서버가 거부함 | 빌드의 검증 키가 서버의 서명 키와 다르거나, `product-key-prefix`가 키와 다르거나, `ContactIdentity`의 주소가 고객 정보와 다릅니다 | 시작 로그의 키 지문을 서버의 값과 비교한 뒤, 접두어와 담당자 주소를 순서대로 확인하세요 |
| 활성화가 `FINGERPRINT_UNAVAILABLE`로 실패함 | 일부 컨테이너와 가상 머신처럼 머신의 고정 식별자를 읽을 수 없습니다 | 상태 응답의 `machineFingerprintAvailable`을 확인하고, 컨테이너에 고정 MAC 주소나 머신 ID를 지정하세요 |
| 오프라인 토큰이 `MACHINE_MISMATCH`로 거부됨 | 다른 머신의 요청에 대해 발급된 토큰입니다 | 애플리케이션을 실행할 머신에서 요청을 생성하세요 |
| 컨테이너를 교체하면 라이선스가 사라짐 | 파일 저장소를 사용하고 있으며 `state-path`가 볼륨에 있지 않습니다 | 파일을 볼륨에 보관하거나, JPA를 추가해 데이터베이스 저장소가 선택되게 하세요 |
| 애플리케이션 실행 중에 라이선스가 갱신되거나 재검증되지 않음 | 애플리케이션에 `@EnableScheduling`이 없습니다 | 어노테이션을 추가하세요 |

## 강제 적용

| 증상 | 원인 | 조치 |
|---|---|---|
| 라이선스 화면까지 403으로 응답함 | `api.version.prefix`가 실제 API 접두어와 달라 열려 있는 경로가 잘못 계산됩니다 | `api.version.prefix`를 실제 접두어로 지정하세요 |
| 유예 기간에 조회는 되고 저장은 403으로 실패함 | `grace-period-mode`가 `READ_ONLY`입니다 | 의도된 동작입니다. 쓰기를 허용하려면 `RESTRICTED`로 지정하세요. 이 경우 기능 게이트만 적용됩니다 |
| 정상 발급된 토큰인데 상태가 `SIGNING_KEY_COMPROMISED`임 | 토큰을 서명한 키가 이 빌드에서 유출로 표시되어 있고, 토큰이 고정된 허용 상한보다 많이 요구합니다 | 현재 서명 키가 포함된 릴리스로 업그레이드하고 그 키로 서명된 토큰을 등록하세요. 유출 키로 다시 서명한 토큰은 결과가 같습니다 |
| 상태가 `CLOCK_TAMPERED`임 | 호스트의 시계가 이전에 관측된 시각보다 과거로 변경되었습니다 | 시계를 동기화한 뒤 다시 검증하세요. 토큰을 새로 등록해도 해제되지 않습니다 |
| `@RequiresFeature`를 지정한 엔드포인트가 기능 없이도 호출됨 | Spring AOP가 클래스패스에 없거나, 같은 빈 내부에서 메서드를 호출했습니다 | `spring-boot-starter-aspectj`를 추가하고, 프록시를 거치지 않는 위치에서는 `FeatureAccess`를 호출하세요 |
| 계약 수량을 넘는 등록이 성공함 | 해당 코드의 카운터가 없거나, 카운터의 코드가 라이선스의 코드와 다르거나, `require`를 호출하지 않았습니다 | 시작 로그에서 카운터 누락 경고를 확인하고, 코드를 비교하고, 항목을 생성하는 위치에서 `quotaGuard.require`를 호출하세요 |
| 거부 응답에 문구 대신 메시지 키가 표시됨 | 메시지 번들에 해당 키가 없습니다 | [라이선스 강제 적용](./enforcing-the-license.md)의 키를 모든 언어에 추가하세요 |
